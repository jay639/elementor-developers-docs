# Arrow Escape: Traffic Puzzle — project spec & conventions

Production Flutter game for iOS + Android. This file is the source of truth for
scope, rules and conventions. Update it when a decision changes.

## Toolchain

- Flutter stable (3.47.x), Dart 3.13. Run commands from `arrow_escape/`.
- Checks that must pass before every commit / at the end of every phase:
  ```sh
  flutter analyze
  flutter test
  (cd packages/arrow_engine && dart analyze && dart test)
  (cd tool && dart analyze && dart test && dart run bin/verify_levels.dart)
  ```
- Levels: `cd tool && dart run bin/generate_levels.dart` regenerates
  `assets/levels/` (deterministic, ~20 s, verifies at the end). Inspect one
  with `dart run bin/show_level.dart 42` or `--daily 2026-10-29`.
- Codegen (freezed / json_serializable):
  `dart run build_runner build --delete-conflicting-outputs`. Generated
  `*.freezed.dart` / `*.g.dart` files are committed.

## Core game

- A board is a grid of arrows (cars). Tapping a car slides it out in its
  direction if the path to the board edge is clear. If blocked it bumps toward
  the blocker and back, and the player loses a heart (3 hearts per level).
  0 hearts = level failed.
- Multi-segment vehicles (trucks) move like a snake: the body follows the head,
  so only the head's ray to the edge matters.
- Rendering uses `CustomPainter` (no Flame). 60fps animations driven by a
  single `Ticker`, haptics, soft sounds.
- Pinch-zoom + pan (`InteractiveViewer`), "show paths" toggle (no undo: it
  made the puzzle trivial), large tap targets
  (nearest-piece hit test with tolerance), double-tap protection (a piece that
  is already animating ignores taps; per-piece debounce).
- Mechanics unlock gradually:
  - Every arrow is multi-segment from level 1 (long, bending "snakes";
    the old L20 trucks unlock was folded into this in Sprint 1).
  - **L40 traffic lights** — a light sits on an empty cell; every successful
    exit toggles all lights. A red light blocks any path that crosses it.
  - **L70 one-way gates** — a gate on an empty cell forces traffic entering
    it to turn and continue in the gate's direction (paths can bend).
    Entering against the arrow is impossible (the vehicle bumps), and gate
    loops never exit. (A gate that merely blocks would be static: a car
    either could never leave or the gate would not matter.)
  - **L100 ambulance** — while the ambulance is on the board, the only other
    vehicles allowed to move are the ones standing in its lane (on its exit
    ray). Moving anything else costs a heart ("Let the ambulance through!").
- Stars per level: 3 = no hearts lost, 2 = one lost, 1 = two lost.

## Levels

- `tool/` is a Dart CLI package: seeded procedural generator + solver.
  Generation is by reverse placement (each newly placed piece must be able to
  exit given the pieces already placed), so every level is solvable by
  construction; the solver then verifies each level and scores difficulty
  (min moves, branching factor, blocker depth).
- Boards use shape masks (car, animals, hearts, letters, landmarks), not just
  rectangles.
- 1500 pre-generated levels shipped as compressed (gzip) JSON assets with a
  smooth difficulty curve and a "breather" (easier) level every 5th level.
- Daily challenge generated on-device from a date seed (same generator, shared
  via the pure-Dart `arrow_engine` package).

## Meta / retention

- City map: every 10 levels builds a city block.
- Collection: Wonders (picture puzzles) and arrow skins.
  - Wonders (`ShapePuzzles`, 23) go from small to cosmic in chapters:
    Garden (ladybug, leaf, flower, butterfly, mushroom, onion), Land
    (cactus, pine tree, volcano, mountain), Sky (raindrop, snowflake,
    cloud, lightning, rainbow, tornado), Space (moon, mars, earth, saturn,
    sun, nebula, galaxy). Galaxy stays last; new wonders slot into a
    chapter. Layers come from a pool of 9 boards per picture (easiest,
    middle, hardest), so small pictures still get three distinct layers. One opens when total stars (campaign + daily + puzzles,
    `Progress.points`) reach its threshold (15 → 1600); each has 3 layers
    (Hard / Harder / Expert, each strictly harder), opened in order,
    generated by the tool into `assets/levels/puzzles.json.gz`. Cleared
    layers colour the picture in.
  - Arrow skins: free Ink (plain one-colour lines); paid skins are visible
    upgrades: Rainbow (per-arrow colours), Ocean/Forest/Sunset (gradient
    lines), Neon (glow), Gold (metallic). `SkinEffect` + `paintArrow`
    draw both the board and the shop previews.
- Coins: skins and Skip level (150 coins, campaign only, no stars).
- Home product tour (after the level-1 tutorial, once): streak, stars,
  coins, collection, daily, city, shop.
- Brand: `paintLogo` (core/widgets/arrow_logo.dart) draws the logo in-app
  and renders the launcher icons (`flutter test test_screens/icon_test.dart`
  then resize; Android mipmaps, iOS AppIcon, assets/branding/).
- Every arrow's body runs straight into its head (the generator forces the
  cell behind the head to be straight behind), so heads never look tilted;
  `headPose` still takes the direction from the road past the head.
- Dead ends: with lights or the ambulance a wrong order can trap the last
  arrows. After each move the controller checks the solver; if no order
  can clear the board it sets `stuck`, the game shows "No way out" with a
  free restart, and Hint explains instead of asking for a video.
- Splash: native splash shows only the background colour (Android 12+
  `splash_blank` icon, iOS launch colour); the Flutter splash grows the
  big logo in, holds, then zooms out.
- Daily streak, daily reward, star rating.

## UI

- Vivid, candy-like look: lilac→peach gradient backdrops, white soft-shadow
  cards, 3D "candy" buttons (`core/widgets/ui.dart`), saturated arrow
  colours (thin lines need strong colour). Light/dark mode. Thick-arrow,
  high-contrast and colorblind (shape/pattern + Okabe-Ito palette) modes.
- Material 3 with a custom theme. Google Font (Fredoka, OFL) bundled as TTF
  assets declared in `pubspec.yaml` — never fetched at runtime, so the
  `google_fonts` package isn't needed.
- Screens: splash, home, level map, game, win/lose, shop, collection
  (pictures + arrow skins), settings, daily challenge.
- `flutter test test_screens --update-goldens` renders the main screens to
  `test_screens/out/` (git-ignored) for design review.
- App size under 40MB.

## Ads (behind `AdService`)

- google_mobile_ads + AdMob mediation adapters (AppLovin, Unity, Meta,
  ironSource/LevelPlay).
- Rewarded: hint, extra heart, double coins, unlock skin.
- Interstitial: none before L10, then at most 1 per 3 levels AND 3 minutes
  (values from Firebase Remote Config). Never before a level starts.
- Banner only on the map screen.
- Google UMP consent (GDPR) + iOS ATT prompt. Test ad IDs in debug; real IDs
  come from flavors / `--dart-define`, never hardcoded. Ads not child-directed.

## In-app purchases (behind `PurchaseService`)

- RevenueCat (`purchases_flutter`). Products: `remove_ads` (non-consumable,
  $3.99, removes interstitials + banner), coin packs (consumable), starter
  bundle. Restore purchases button. Entitlements checked via RevenueCat, not
  local flags.

## Backend

- Firebase: anonymous auth, Firestore cloud save (synced with local save),
  Remote Config, Analytics (`level_start`, `level_complete`, `level_fail`, ad
  and purchase events), Crashlytics.

## Security

- Firebase App Check (Play Integrity / App Attest). Firestore rules: a user can
  read/write only their own doc.
- Local save in Hive, encrypted with a key stored in `flutter_secure_storage`.
  Coins/progress carry an HMAC to detect tampering.
- No secrets in code. Release builds use `--obfuscate --split-debug-info`,
  R8/ProGuard enabled.

## Architecture

- Riverpod (state), go_router (navigation), feature-first folders, freezed
  models for app/UI state and persisted data.
- The game engine (`packages/arrow_engine`) is pure Dart with zero
  dependencies so the CLI tool, the app and the tests share it. Its hot-path
  types (board state, pieces) are hand-written immutable classes rather than
  freezed, because the solver creates millions of them.
- Unit tests for the engine, generator and solver; widget tests for key
  screens. Flavors: `dev` / `prod` (`lib/main_dev.dart`, `lib/main_prod.dart`,
  Android productFlavors, iOS schemes).

## Status / decisions log

- Phase 1 done: engine (`packages/arrow_engine`), theme, game screen,
  splash/home/settings, Android `dev`/`prod` productFlavors. Settings and
  progress are in-memory until phase 3 adds the encrypted Hive store.
- Phase 2 done: generator, analyzer, campaign plan, daily challenge,
  `tool/` CLI, 1500 levels in 15 gzip packs (~160 KB), daily screen.
- Campaign: levels 1–3 and the first level of each mechanic (20, 40, 70,
  100) are hand-made (`samples.dart`); the rest are generated to a target
  curve (`Campaign.targetDifficulty`, ~15 → ~68) with every 5th level a
  breather at 60% of the curve. A new mechanic appears in each of the 4
  levels after its introduction, then in a share of later levels.
- Generator: reverse placement (solvable by construction). Each gate is
  placed with a "feeder" car that turns through it, so no gate is
  decorative; unused ones are dropped. The ambulance gets an empty lane
  reserved; only cars placed after it, in that lane, leave before it.
  Lights and ambulance levels are re-verified with the solver.
- Difficulty (0–100) = f(log pieces, blocker-chain depth, share initially
  blocked by cars/lights, blockers per path, solver dead ends, mechanics).
  `generateForTarget` adapts board size/density after each candidate.
  Min moves always equals the vehicle count (each leaves once).
- Determinism: generation uses `Rng` (own xorshift) and `detLn` (log from
  basic IEEE ops) instead of `dart:math` Random/log/pow, so the daily is
  bit-identical on every device. Golden hashes in
  `packages/arrow_engine/test/generator_test.dart` catch accidental
  changes; bump `DailyChallenge.version` when a change is intended.
- Daily: local calendar day, always a full crowded rectangle; target starts
  above campaign level 20 (66 on 2026-11-01) and rises 0.1 a day (+2 at
  weekends) to 90, with bigger boards as it rises. Generated on a
  background isolate. Progress stores best stars per day.
- iOS schemes for flavors need Xcode and are set up in phase 7.
- Double-tap protection: a vehicle that is bumping/returning ignores taps,
  repeat taps on one vehicle within 280 ms count once, and taps on the cell
  of a vehicle that is driving away are swallowed (so the tap tolerance
  can't hand them to a neighbour).

- Phases 3–8 done:
  - Save: one `SaveData` document (progress, coins, skins, streak, daily
    reward, settings, claimed bundles, revision/updatedAt). Economy rules
    are pure functions in `features/save/domain/economy.dart`.
    `SaveController` stamps revisions and persists every change.
  - Coins: first clear 10 + 5/star, replay 2; daily 50 + 10/star; daily
    reward ladder 20/30/40/50/60/80/150 (resets after a missed day).
    Streak = consecutive days with a win.
  - Ads: `AdService` (AdMob impl, `NoAdService` fallback). Interstitials
    only after finished campaign levels, governed by `InterstitialPolicy`
    + Remote Config. Banner only on the map. Test ids unless release ids
    are dart-defined; a prod build without ids has ads off.
  - IAP: `PurchaseService` (RevenueCat impl, unavailable fallback).
    Entitlements `no_ads`, `starter` from CustomerInfo only.
  - Firebase is optional at runtime (`initFirebase` returns false without
    config → offline services). Cloud save merges monotone progress and
    takes balances from the newer copy (`mergeSaves`).
  - Security: encrypted Hive + HMAC (`SaveCodec`), keys in secure storage,
    App Check, `firebase/firestore.rules`, R8, obfuscated release script.
  - Accessibility: each vehicle/light is a semantics node (activate to
    move); guideline tests in `test/a11y`.
  - CI: `.github/workflows/arrow_escape.yml` runs every check and builds
    split-per-ABI release APKs (dev flavor) with a 40 MB budget.
- Sprint 1 (growth plan) done:
  - Arrows are long thin "snakes" (2–16 cells by level) drawn on a dot
    grid; trucks are no longer a separate mechanic (L20 unlock removed).
  - Difficulty tiers: from L12 every 10th level is Hard (2× first-clear
    coins) and every 50th Super Hard (3×); faster curve.
  - Onboarding: level 1 is a guided tutorial (hand, blocked-path demo,
    only the highlighted arrow accepts taps, skippable), pinch hint on
    small cells, one-time popups for each mechanic.
  - Analytics: typed events (README "Analytics"), attempt counter per
    level in the save, user properties via `AnalyticsSync`, AdMob paid
    events, consent mode v2, in-app analytics opt-out.
- Sprint 2: boards are packed (tails grow into leftover cells) up to
  18x26 with ~55 arrows; level 2 is a warm-up and level 3 on is hard,
  rising to level 1500; tiers start at L9; arrow line width/head size are
  capped in logical px; undo removed; Fredoka font + vivid UI; picture
  puzzle collection.
- Sprint 3: generator rebuilt for competitor-style boards: arrow lengths
  mix many short (2-3) with medium and a few long snakes (up to 30),
  bodies wind and hug neighbours so arrows interlock; placement prefers
  blocking arrows that are still free and skips edge arrows that could
  never be blocked; tails grow a little into holes. Mostly rectangular
  boards (65%), max 15x20 so boards fit the screen; level 3 on is hard.
  Sharper, larger arrowheads; dark mode is true black; collection tabs
  stay fixed while content scrolls.
- Sprint 4: boards are dense knots: longer snakes from early levels
  (up to 36 cells), placement rewards bodies that sit right in front of
  another arrow's head (head-into-tail chains), tails grow up to 10 cells
  into pockets, then a fill pass drops short arrows into remaining gaps.
  Bigger minimum boards (150→280 cells; breathers smaller). Curve
  recalibrated (60→~76); verifier tolerances widened for per-level noise.
  Crisp pointed arrowheads (~0.46 cell). Settings use inset grouped
  lists with platform switches (`Switch.adaptive`) so they feel native on
  iOS and Android. The logo
  is shown from assets/branding/logo.png (painting it live crashed the CI
  emulator's GPU).
- Sprint 5: arrow COUNT is the progression axis (`Campaign.arrowTarget`):
  L2 12, L8 ~30, L100 ~49, L500 ~77, L1500 ~110 (cap 120); breathers
  0.92x, Hard 1.12x, Super Hard 1.25x. `generateForArrows` sizes the
  board to the count (up to 24x32), length mix in four bands (tiny 2,
  short 3-4, medium 5-9, long 10+), keeps the hardest candidate by
  `hardness` (the 0-100 score saturates on big boards). Verifier checks
  counts, not scores. Daily: 85 arrows at launch, +1 per 10 days, +6 at
  weekends, max 110, always 24x32. Wonders: 28 (ladybug) to ~80 arrows,
  +25% per layer, capped by picture capacity. Boards with cells under
  17 dp open zoomed out, then zoom in to ~25 dp cells (pinch out / Fit
  to see all). "Halfway there 😄" cheer at 50% on 20+ arrow boards
  (and "Almost there 🤩" at 90% on Hard levels). Store rating:
  `ReviewPolicy` (3-star campaign win from L6, no interstitial that
  win, 40 levels + 30 days apart, max 3 asks) via `in_app_review`; the
  stores never reveal whether/what a player rated, and pre-asking to
  filter happy players is forbidden, so that can't be targeted.
  Settings has "Rate Arrow Escape" (store listing).
- Sprint 6: harder from L3. Arrow targets climb fast (L2 14, L3 ~27,
  L5 ~36, L8 ~46, L100 ~60, L500 ~91, cap 120). No trivial patterns:
  placement, gap fill, tail growth and ambulance-lane arrows reject
  same-direction queues (a same-way arrow right in front of a head) and
  rows (same-way heads side by side); a test guards it. Gap arrows are
  slotted into the play order as late as possible (`_insertRank`, ranks
  instead of placement index) so they start blocked instead of being
  free edge stubs. The splash animation starts once the logo image is
  decoded (first launch after install showed it mid-zoom).
- Sprint 7: solve TIME is the progression axis. `LevelStats.effort` =
  sum over the solution of (arrows left + 1) / (free arrows + 1), a
  model of how long a person hunts for the next free arrow; it never
  saturates. `generateForEffort` adapts the arrow count to land within
  3% of a target. Campaign: `Campaign.effortTarget` rises every level
  (~120 at L3, ~240 at L8, ~330 at L100, ~570 at L500, ~840 at L1500;
  Hard x1.25, Super Hard x1.45); no more breather levels. Daily:
  `effortFor` 500 at launch +1/day, +60 at weekends, max 950. Wonders:
  each layer >= 1.2x the effort of the previous (ladder 1 / 1.4 / 1.9,
  scaled down for thin pictures). The verifier checks effort, not
  counts. Show paths draws every road the same (grey dashes): it never
  reveals which arrow is free. Board background is fainter
  (`Palette.boardLight/Dark`). Thick arrows: stroke 0.2 cell up to 7.5
  px with a proportionally bigger head. Unfinished levels resume
  (`ResumeStore`, local Hive box, kept out of the cloud save because it
  changes every move): exits in order + hearts + mistakes, replayed by
  `PlaySession.resume`; cleared on win, loss, restart or skip.
- Sprint 8: package `com.riseivo.arrow.escape.game` (Android
  applicationId/namespace, Kotlin MainActivity path, iOS bundle id; dev
  flavor adds `.dev`). Harder: effort targets 1.5x (L3 ~180, L8 ~350,
  L100 ~500, L500 ~880, ~1045 at L1500, slower past 900), boards up to
  26x34 and 160 arrows; daily 750 +1.5/day, +90 weekends, max 1250;
  Wonders base 180 + 20 per picture. Wrong moves play `Sfx.error` (a
  two-tone buzz; the old soft bump sound is gone). Show paths: violet
  dashes on a board-coloured halo, drawn over resting arrows but clipped
  around every arrowhead, so roads read on every skin. Normal arrows
  0.145 cell up to 5.5 px (thick mode 0.2 / 7.5). Privacy policy:
  `assets/legal/privacy_policy.html` in a WebView (Settings → Privacy
  policy, `/privacy`), hosted copy `docs/privacy-policy.html` for
  https://www.riseivo.com/arrow-escape/privacy-policy. Purchases: silent
  RevenueCat sync on Android start when nothing is active (auto-restore);
  iOS keeps the Restore button. CI prints the Meta key hash of the
  signing cert.
- Sprint 9: generator calibrated on the genre leader's 1,055 levels
  (research only; nothing copied into the app). Theirs: ~80 arrows on
  ~27x32 boards, arrows 9.2 cells (36% are 10+), 12-20% free at start,
  chain depth 26-44. Ours now: length mix 12% tiny / 18% short / 34%
  medium / 36% long (`generateForEffort` defaults), turn chance 0.36,
  tails grow up to 8, gap fill up to 10 cells, greed 8-16, candidates
  scored on effort miss + a penalty above 18% free arrows; boards up to
  32x40 (220 arrows). Effort targets: L3 ~280, L8 ~545, L100 ~770,
  L500 ~1,175, L1500 ~1,330 (softer past 1,100, cap 1,500); campaign
  boards are always portrait rectangles (3:4 or 4:5 once targets pass
  900). Daily 1,100
  +2/day, +150 weekends, max 1,350. Wonders 280 + 30 per picture. Wrong
  move: tapped arrow turns red (`FlashAnimation.alert`), bump sound +
  `error` buzzer, double buzz on the vibration motor (`vibration`
  package; system haptics are silent when touch feedback is off). Show
  paths: soft solid lines under the arrows (no dashes); no board fill,
  only dots. Offline rewarded message mentions the connection.
- Sprint 10: arrows 18% of a cell (3.2-6.8 dp), thick 22% (3.8-8.3 dp)
  via `BoardStyle.minStroke/maxStroke`. One-time Fit-button coach mark
  (`Tips.fitBoard`, `ProductTour` in the board) the first time the board
  is zoomed in, never with the tutorial or pinch hint. Halfway / almost

- Sprint 11: gentle start. Levels 2-20 use a fixed effort ramp

  Push notifications are not implemented yet (no firebase_messaging).

then stop and summarize.

## Conventions

- `package:` imports only; no relative imports across features.
- No secrets, ad unit IDs or API keys in source. Use `--dart-define` /
  flavor config.
- Services that touch platform plugins sit behind an interface and get a no-op
  / fake implementation in tests.
- Keep engine code free of Flutter imports.
